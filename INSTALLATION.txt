INSTALLATION INSTRUCTIONS
=========================

Quick Start:
------------
1. Extract this ZIP file to your desired location (e.g., C:\K2\)
2. Double-click K2.exe to launch the application
3. On first run, configure paths to external software (see below)
4. See K2_USER_GUIDE.md for detailed instructions


SYSTEM REQUIREMENTS
===================

Minimum:
- Windows 10 or Windows 11
- 8 GB RAM
- 10 GB free disk space
- Internet connection (for EPA CompTox API - optional)

Recommended:
- 16 GB RAM
- SSD storage
- Multi-core processor


EXTERNAL SOFTWARE REQUIRED
==========================

K2 requires the following external tools, which must be downloaded and 
installed separately due to licensing requirements:

1. ProteoWizard MSConvert (for raw instrument data conversion)
   -----------------------------------------------------------
   - Download: https://proteowizard.sourceforge.io/
   - Required for: Converting vendor raw data to .mzML format
   - Supports common GC-MS / LC-MS vendor formats (Agilent .D,
     Bruker .d, Thermo .raw, Sciex .wiff, Waters .raw, Shimadzu .lcd)
   - K2 Annotator has been tested against Agilent .D folders;
     other formats are accepted on a best-effort basis
   - Install to default location or note the path to msconvert.exe
   - Typical path: C:\Program Files\ProteoWizard\msconvert.exe

2. MZmine 3.x or 4.x (for feature detection and deconvolution)
   -------------------------------------------------------------
   - Download: https://github.com/mzmine/mzmine/releases
   - Required for: Processing .mzML files, detecting features
   - Download the Windows installer (mzmine-windows-installer.exe)
   - Note the path to mzmine_console.exe after installation
   - Typical path: C:\Program Files\mzmine\mzmine_console.exe
   - Tested with MZmine 4.x (4.8.30 in the current development setup).
     MZmine 3.x is also supported. Note: the CLI flag
     `--mzmine-memory` exposes MZmine's `KeepInMemory` enum directly;
     the valid values changed between major versions. K2 Annotator's
     current default is `none` (matches MZmine 4's own fallback).


FIRST-TIME SETUP
================

1. Launch K2.exe

2. Click "Start New Analysis"

3. Select your entry point:
   - "Raw Instrument Data" - Full pipeline from any vendor raw format
     (Agilent .D, Bruker .d, Thermo .raw, Sciex .wiff, Shimadzu .lcd, etc.)
   - "Instrument Files (.mzML)" - Skip conversion step
   - "Deconvoluted Spectra (.MSP)" - Library matching only

4. Configure external tools:
   - Browse to locate msconvert.exe (if starting from raw data)
   - Browse to locate mzmine_console.exe (if using MZmine)
   - Check "Save as default" to remember paths

5. Configure analysis parameters:
   - Select your spectral library (.CSV or .MSP format)
   - Select RI calibration file (optional)
   - Enter EPA API key (optional, for hazard data)

6. Run your first analysis!


EPA COMPTOX API KEY (OPTIONAL)
==============================

The EPA CompTox API key enables hazard-data enrichment. Since version
3.1.0 the key is handled as a secret:

- It is never placed on a command line. The GUI and the pipeline hand it
  to the matching step through the environment variable K2_EPA_API_KEY.
- Command-line users can set K2_EPA_API_KEY themselves instead of passing
  --api-key, e.g. (Windows):   set K2_EPA_API_KEY=your_key_here
- The GUI remembers the key in %USERPROFILE%\.k2\credentials.json
  (a separate file with an explanatory comment). It is NOT written to
  k2_defaults.json, to .K2 project files, or to .K2config presets, so
  those files can be shared safely. Delete credentials.json, or clear
  the key in the Analysis Parameters screen, to forget it.


WHAT'S NEW IN 3.1.0 (LAUNCH / PIPELINE)
=======================================

- Results are never overwritten: a second run with the same project
  name goes to results\<name>_2, _3, ...
- Every run writes pipeline_log.txt (the full console log) and, when
  MZmine runs, mzmine_log.txt (the complete, unfiltered MZmine output)
  into its results folder.
- Zero-match runs finish with a warning (exit code 2) and still write
  the feature summaries.
- "Thread Count" in the MZmine screen is now honoured; tick
  "Serialise MZmine import (1 thread)" to restore the old
  single-threaded import on machines that hit the unsafe-memory-access
  crash.
- New analysis options: max library peaks, RI extrapolation mode
  (spline/linear) and "allow runs with no blank samples".
- K2.bat prefers the "py -3" launcher (avoids the Microsoft Store
  python alias) and re-installs dependencies whenever requirements.txt
  changes.

TROUBLESHOOTING
===============

Problem: K2.exe won't start
Solution: 
- Ensure you extracted the entire ZIP contents (not just K2.exe)
- Check that Windows Defender isn't blocking the file
- Try running as Administrator

Problem: "msconvert.exe not found"
Solution:
- Download and install ProteoWizard
- In K2, use Browse button to locate msconvert.exe
- Check "Save as default"

Problem: MZmine processing fails
Solution:
- Ensure MZmine 3.x is installed (not MZmine 2)
- Verify mzmine_console.exe path is correct
- Check available RAM (MZmine needs significant memory)

Problem: No matches found (run ends with "no Level-2 matches", exit code 2)
Solution:
- Verify library file format (CSV needs peaks_json column)
- Check RI calibration file format
- Ensure blank identifier matches sample names
- Try adjusting matching thresholds (see K2_USER_GUIDE.md
  "Level 2 Matching Criteria" for the current gating rules)
- Read results\<name>\pipeline_log.txt: it records the sample
  classification, BFF filtering and matching diagnostics for the run

Problem: "python" opens the Microsoft Store when K2.bat runs
Solution:
- Install Python from https://www.python.org/downloads/ (K2.bat then
  uses the "py -3" launcher automatically), or disable the Store alias
  under Settings > Apps > Advanced app settings > App execution aliases

Problem: Pipeline refuses to start with "Insufficient free disk space
         for MZmine scratch"
Solution:
- MZmine memory-maps mzML data into temp files; on most workflows
  the peak temp usage is 1.5-3x the total input mzML size. The
  pre-flight check refuses to start if the scratch volume has less
  than 1.5x free.
- Free space on the scratch volume (defaults to %TEMP%), or pass
  --mzmine-temp pointing at a roomier local drive. Network shares
  (Z:, SMB mounts) are NOT supported as scratch — Java NIO
  memory-mapping fails on them.
